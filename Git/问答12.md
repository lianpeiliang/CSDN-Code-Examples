# 问答 12：不同文件的改动是否会冲突

## 提问

假设电脑 B 的本地分支和电脑 A 裸仓库中的对应远端分支从同一个提交开始，各自又产生了新的提交。电脑 B 先获取电脑 A 上的远端更新，再尝试将其合并到本地分支。如果双方的代码改动涉及不同文件，合并时一定会发生冲突吗？

## 我的回答

我认为会发生冲突，因为远端和本地分别有新的提交，直接推送时可能出现非快进更新。

## 注释

不一定会发生合并冲突。两边分别有新的提交，可能导致直接 `git push` 因非快进更新而被拒绝，但这与合并是否冲突是两个不同的问题。

- **非快进更新**描述提交历史已经分叉，直接推送无法在保留远端提交的情况下更新远端分支。
- **合并冲突**描述 Git 无法自动整合双方对文件内容的修改。

如果两边改动的是不同文件，Git 通常可以自动合并。合并完成后，再推送更新后的本地分支。


## 补充问答：自动合并

### 提问

什么是 Git 的自动合并？什么情况下会发生合并冲突？

### 回答

自动合并是指 Git 根据提交历史和文件差异，将双方的改动自动整合起来，不需要手动逐行修改。

如果双方修改不同文件，Git 通常可以自动合并。同一文件中彼此不重叠的改动，也通常可以自动合并。如果双方都修改了同一段内容，且 Git 无法判断应该采用哪种改动，就会发生合并冲突。需要手动编辑冲突文件，再运行 `git add` 标记冲突已解决，并完成合并提交。

### 注释

自动合并成功后，Git 可能会创建合并提交来记录两边历史的汇合。如果本地分支只是落后于远端，Git 也可能通过快进直接移动本地分支指针。自动合并成功只表示 Git 能整合文本改动，不代表程序逻辑一定正确。

## 补充问答：快进更新

### 提问

如果本地分支只是落后于远端，Git 通过快进移动本地分支指针是什么意思？

### 回答

如果本地分支没有自己的新提交，只是比远端少了几个提交，Git 可以直接把本地分支指针移到远端最新提交的位置。这个操作称为快进（fast-forward）。

```text
更新前
本地分支：A──B
远端分支：A──B──C──D

快进后
本地分支：A──B──C──D
远端分支：A──B──C──D
```

### 注释

快进只移动本地分支指针，不会创建额外的合并提交。只有当本地分支的提交历史是远端分支历史的祖先时，才可以这样更新。

## 补充问答：未暂存修改时运行 `git pull`

### 提问

如果本地文件有修改，但还没有运行 `git add`，此时执行 `git pull` 会发生什么？

### 回答

`git pull` 会先获取远端更新，再按配置执行合并或变基。未暂存的本地修改不会因此被忽略。

如果远端更新不涉及本地修改的文件，Git 通常可以继续整合，未暂存的修改会留在工作区。如果远端也要更新本地修改过的文件，Git 通常会停止整合，并提示本地修改可能被覆盖，以保护这些修改。

### 注释

运行前可以用 `git status` 查看工作区状态。Git 官方文档说明，当未提交的本地修改与合并需要更新的文件重叠时，`git pull` 或 `git merge` 会停止操作。[Git merge 文档](https://git-scm.com/docs/git-merge)

## 补充问答：先保存本地修改再拉取

### 提问

如果本地有未暂存修改，`git pull` 因这些修改可能被覆盖而停止，可以先如何处理这些修改，再重新拉取远端更新？

### 我的回答

可以先提交本地修改，再拉取远端更新。

### 注释

回答正确。先运行 `git add` 将修改放入暂存区，再运行 `git commit` 保存为本地提交，然后执行 `git pull`。如果暂时不想创建提交，也可以使用 `git stash` 暂存这些未提交修改，拉取完成后再恢复。
