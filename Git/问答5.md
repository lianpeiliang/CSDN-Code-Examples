# 问答 5：将远端分支整合到当前分支

## 提问

如果当前检出的是本地 `feature` 分支，并运行 `git pull lan control`，远端 `lan/control` 分支的更新会被整合到本地 `feature` 分支。这相当于在本地 `feature` 分支上获取并整合远端 `control` 分支的代码，对吗？

## 回答

对，理解正确。运行命令后，当前检出的分支仍是本地 `feature`，远端 `lan/control` 的更新会被整合到 `feature`。Git 根据 pull 配置执行合并或变基。

## 补充问答：`merge` 与 `rebase`

### 提问

我知道“合并”指的是 `merge`。那么，`merge` 和 `rebase` 分别是什么操作？

### 回答

`merge` 和 `rebase` 都可以将一个分支的更新整合到另一个分支。

假设 `main` 和 `feature` 分支各自有新的提交：

```text
A──B──C  main
    \
     D──E  feature
```

在 `feature` 分支上运行 `git merge main`，会把 `main` 的更新合并进 `feature`。当两个分支已经各自前进时，Git 通常会创建一个合并提交来记录这次汇合：

```text
A──B──C────M  feature
    \      /
     D──E──
```

在 `feature` 分支上运行 `git rebase main`，会把 `feature` 上的提交重新应用到 `main` 的最新提交之后：

```text
A──B──C──D'──E'  feature
```

简单来说，`merge` 保留分支汇合的记录；`rebase` 会重新应用提交，使提交历史呈现为一条直线。`D'` 和 `E'` 是重新生成的提交。
