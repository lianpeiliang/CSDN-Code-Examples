# 问答 8：补丁文件的作用

## 提问

如何理解 Git 可以将改动保存为补丁文件，并将补丁应用到其他代码副本？

## 解释

补丁文件可以理解为一份用文本记录的改动说明，其中包含哪些文件的哪些行被删除或新增。其他人可以将补丁应用到自己的代码副本，让 Git 按照补丁中的内容修改文件。

例如，导出尚未暂存的改动：

```bash
git diff > changes.patch
```

在另一份代码副本中应用补丁：

```bash
git apply changes.patch
```

应用后，改动会出现在工作区，可以继续检查、暂存并提交。

## 注释

补丁主要用于传递代码改动内容，本身不等于 Git commit，也不包含完整的提交历史。

## 补充问答：在另一台电脑应用补丁

### 提问

在电脑 A 上生成补丁并在电脑 B 的本地仓库中应用后，电脑 B 上对应文件会发生什么变化？

### 回答

在电脑 A 的本地仓库中，可以将尚未暂存的修改导出为补丁文件，再将补丁带到电脑 B 的本地仓库中应用。如果电脑 A 在某个文件中新增了一行，并且补丁能够匹配电脑 B 中对应文件的内容，那么应用补丁后，电脑 B 的文件也会新增这一行。

### 注释

理解正确。`git apply` 通常会把改动应用到电脑 B 的工作区，修改尚未暂存或提交。如果补丁所依赖的文件内容与电脑 B 的文件差异较大，Git 可能无法应用补丁。

## 补充问答：应用补丁所需的文件条件

### 提问

在电脑 B 上应用补丁时，对应文件是否必须与电脑 A 生成补丁前的文件完全一致？

### 回答

不要求整个文件完全一致。补丁需要在电脑 B 的文件中找到与改动相关的内容和上下文。例如，补丁在某个函数附近新增一行，只要电脑 B 上对应位置仍有足够匹配的内容，补丁通常就能应用。

### 注释

如果电脑 B 也修改了补丁涉及的位置，Git 可能无法找到匹配内容，导致补丁应用失败或需要手动处理。文件其他无关部分不同，通常不会妨碍应用。
