# 问答 4：整合远端更新与处理冲突

## 提问

如果运行 `git fetch lan` 后，`lan/control` 有了新提交，而本地 `control` 还没有这些提交，可以用什么命令将远端更新整合到本地 `control`？

## 回答

通常会先提交本地已经完成的修改，再获取并整合远端更新。如果使用 `git pull`，Git 会尝试自动合并。若合并成功，就可以继续工作；若发生冲突，Git 会提示需要处理的文件。此时需要检查双方的修改，讨论并确定如何解决冲突，再完成合并。

## 回复

你描述的是把远端更新整合到本地的过程，通常通过 `pull` 或 `merge` 完成：

- `git pull lan control` 会获取远端 `control` 分支的更新，再尝试合并到当前分支。
- 如果已经运行了 `git fetch lan`，可以切换到本地 `control` 分支，再运行 `git merge lan/control`。

Git 能自动合并时，命令会完成合并；遇到冲突时，会标出需要处理的文件，你再检查并解决冲突。自动合并成功表示 Git 能合并这些改动，不代表代码逻辑一定没有问题。

### 回答

在已经运行 `git fetch lan` 的前提下，如果要把 `lan/control` 合并到本地 `control`，可以先切换到本地 `control` 分支，再运行：

```bash
git merge lan/control
```

也可以运行 `git pull lan control`，它会获取远端 `control` 分支，并尝试将更新合并到当前所在的分支。

## 补充问答：`git pull` 整合到哪个分支

### 提问

运行 `git pull lan control` 时，如果当前检出的分支不是本地 `control`，而是其他分支，Git 是否仍会将远端 `lan/control` 的更新整合到当前分支？

### 回答

是的。`git pull lan control` 会获取远端 `lan` 上的 `control` 分支，并将更新整合到当前检出的本地分支。该命令不会自动切换到本地 `control` 分支。

例如，如果当前位于本地 `feature` 分支，运行 `git pull lan control` 后，远端 `lan/control` 的更新会被整合到 `feature`。如果要更新本地 `control`，应先切换到本地 `control`，再执行该命令。
