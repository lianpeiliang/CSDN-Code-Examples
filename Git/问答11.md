# 问答 11：远端拒绝非快进推送

## 提问

如果电脑 B 要推送的分支与电脑 A 裸仓库中的同名分支各自包含新的提交，A 一定会接受这次推送吗？如果不接受，B 应该如何处理？

## 我的回答

如果两边的分支各自有新的提交，远端通常不会接受直接推送。电脑 B 需要先获取远端更新，将远端提交与本地提交整合，再推送。

## 注释

回答正确。远端分支已经包含本地没有的提交时，直接推送通常会因非快进更新而被拒绝。可以在电脑 B 上运行 `git pull`，或先运行 `git fetch` 再执行 `git merge`，将远端提交整合到本地分支，然后再运行 `git push`。

如果合并时发生冲突，需要先解决冲突，再运行 `git add` 并完成合并提交。没有冲突时，Git 通常可以自动整合。

## 补充问答：非快进更新

### 提问

什么是非快进更新？

### 回答

非快进更新是指推送时，远端分支已经包含本地没有的提交，而本地要推送的提交并不是从远端最新提交继续发展的。直接推送会使远端分支指针移到另一条提交线上，可能跳过远端已有的提交，因此 Git 通常会拒绝这次推送。

例如：

```text
远端：A──B──C
          \
本地：     D
```

本地的 `D` 和远端的 `C` 是从 `B` 分开的。先通过 `git pull`（或 `git fetch` 后 `git merge`）将远端提交整合到本地，再推送，就能保留两边的提交历史。
