# 问答 7：查看暂存状态

## 提问

运行 `git add` 后，如果想确认哪些文件已经进入暂存区、哪些修改还没有暂存，可以运行什么命令？

## 回答

运行 `git status`。

## 注释

回答正确。`git status` 会显示工作区和暂存区的状态，包括已暂存、尚未暂存以及未跟踪的文件。

## 补充问答：查看代码差异

### 提问

如果想查看已经暂存、准备提交的具体代码差异，可以运行什么命令？

### 回答

可以使用 `git diff -p` 查看代码差异。

### 注释

`git diff -p` 默认显示尚未暂存的改动，并以补丁格式输出。查看已经暂存、准备提交的改动，应使用 `git diff --staged`，也可以使用 `git diff --cached -p`。`-p` 表示以补丁格式显示差异。

## 补充问答：补丁格式

### 提问

什么是补丁格式？

### 回答

补丁格式（patch）是一种用文本表示代码差异的格式。它会标出文件名和变更位置，并用符号说明哪些行被删除、哪些行被新增。

```diff
- print("Hello")
+ print("你好")
```

### 注释

在差异内容中，`-` 表示旧内容中被删除的行，`+` 表示新增加的行。Git 使用补丁格式展示改动，也可以将补丁保存为文件并应用到其他代码副本。

## 补充问答：`staged` 的含义

### 提问

Git 中的 `staged` 是什么意思？

### 回答

`staged` 表示“已暂存”。在 Git 中，修改通过 `git add` 放入本地暂存区后，就处于 staged 状态，等待纳入下一次 `git commit`。

例如，`git diff --staged` 可以查看已经暂存、尚未提交的改动。
