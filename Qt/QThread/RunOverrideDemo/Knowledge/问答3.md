# 问答3：重写 `run()` 和 Worker-object 分别适合什么场景？

## 问题

继承 `QThread` 并重写 `run()`，以及把独立的 `Worker` 对象移入带事件循环的 `QThread`，是不是 Qt 中常见的两种线程用法？它们各自适合什么场景？还有其他选择吗？

## 回答

这两种都是 Qt 中常见的 `QThread` 用法，但不是 Qt 多线程的全部方案。

|             用法              |                                              线程里主要怎么工作                                              |                                         适用场景                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 继承 `QThread` 并重写 `run()` | `start()` 在新线程执行 `run()`。通常在 `run()` 中执行一段明确的任务；如果没有调用 `exec()`，线程就不运行事件循环。 | 一次性、流程清楚的任务，可以把步骤按顺序写在 `run()` 中，并由这段代码决定何时完成或退出。例如本项目的 `RunOverrideDemo` 进度循环。 |
| `QThread` 加 Worker-object    | Worker 通过 `moveToThread()` 归属工作线程，线程事件循环处理发给 Worker 的排队槽和事件。                          | 适合把长期工作的对象、它的槽和事件放在一起管理。Worker 可以使用依赖事件循环的对象，例如 `QTimer`、`QTcpSocket`；但这些对象并非只能通过 Worker-object 使用。 |


如果只是要并行执行很多彼此独立的任务，还可以考虑 `QThreadPool`/`QRunnable` 或 `QtConcurrent::run()`。线程池会管理和复用线程，不必为每项任务手动维护一个 `QThread`。

## 选择方式

- **一次任务，流程自包含：**可以重写 `run()`。
- **线程要长期处理请求、定时器或事件：**通常采用 Worker-object 和线程事件循环。
- **很多彼此独立的并行任务：**考虑 `QThreadPool` 或 `QtConcurrent`。

参考：[Qt `QThread` 文档](https://doc.qt.io/qt-6/qthread.html) · [Qt 多线程技术概览](https://doc.qt.io/qt-6/threads-technologies.html) · [Qt `QThreadPool` 文档](https://doc.qt.io/qt-6/qthreadpool.html)

## 追问：“由代码决定何时完成或退出”是什么意思？

### 问题

重写 `run()` 适合“把一项独立任务按顺序写在 `run()` 中，并由这段代码决定何时完成或退出”。这里的“决定执行过程”具体是什么意思？

### 回答

意思是任务的执行步骤和结束时机都写在 `run()` 函数里。例如，`RunOverrideDemo` 的 `run()` 循环更新进度、检查取消请求；进度达到 100，或者发现中断请求后，函数就返回，线程这一轮执行随之结束。

这种写法不需要另外通过信号槽逐步调度任务。它表示由程序编写者控制任务逻辑和退出条件，**不表示可以控制操作系统如何调度 CPU**。

## 追问：重写 `run()` 后也能调用 `exec()`，为什么还需要 Worker-object？

### 问题

如果继承 `QThread` 并重写 `run()`，也可以在其中调用 `exec()` 来启动事件循环，那么这种写法是否同样可以使用 `QTimer`、`QTcpSocket` 等对象？Worker-object 写法相比之下有什么不同？

### 回答

可以。重写 `run()` 后，在新线程中创建和使用 `QTimer`、`QTcpSocket` 等对象，再调用 `exec()`，就可以让该线程的事件循环处理它们产生的事件。Qt 默认的 `QThread::run()` 本身也会调用 `exec()`。

两种写法的区别主要是对象组织方式，而不是能不能运行事件循环：

- **重写 `run()` 并调用 `exec()`：**可以在 `run()` 中初始化工作对象并启动事件循环。但 `QThread` 对象本身仍属于创建它的线程，因此定义在 `QThread` 子类上的普通槽不会因为调用了 `exec()` 就自动转到工作线程执行。
- **Worker-object：**把独立的 `QObject` Worker 移到工作线程。Worker 的线程归属、排队槽和处理事件的代码集中在 Worker 对象中，由工作线程的事件循环调度，通常更容易组织需要长期接收多个请求的工作对象。

因此，Worker-object 是一种方便组织线程事件和工作槽的常见写法，并不是使用事件循环或 `QTimer`、`QTcpSocket` 的唯一方式。无论采用哪种方式，依赖事件循环的对象都应在其所属线程中创建和使用。

参考：[Qt `QThread` 文档](https://doc.qt.io/qt-6/qthread.html) · [Qt：线程与 QObject](https://doc.qt.io/qt-6/threads-qobject.html)

## 追问：调用 `exec()` 后，普通槽会自动转到工作线程吗？

### 问题

如果在重写的 `run()` 中调用 `exec()` 启动了工作线程的事件循环，那么定义在 `QThread` 子类中的普通槽是否也会自动在工作线程执行？为什么？

### 回答

不会自动转过去。`exec()` 启动的是**调用它的当前线程**中的事件循环，不会改变 `QThread` 对象本身的线程归属。槽具体在哪个线程执行，要看连接方式和接收对象的线程归属。

假设 `MyThread` 对象是在 GUI 主线程创建的，那么它的线程归属仍是 GUI 主线程。默认的 `Qt::AutoConnection` 会在信号发出时检查：发信号时所在的线程是否就是接收对象所属的线程。相同则直接调用；不同则排队到接收对象所属线程的事件循环。

```cpp
// 按钮和 MyThread 对象都属于 GUI 主线程：AutoConnection 直接调用
connect(button, &QPushButton::clicked,
        &myThread, &MyThread::doWork);

// 假设信号在工作线程发出，而 myThread 对象仍属于 GUI 主线程：AutoConnection 排队
connect(worker, &Worker::someSignal,
        &myThread, &MyThread::doWork);
```

所以，“排队调用”（queued invocation）描述的是**实际采用的投递方式**；`AutoConnection` 是决定采用直接调用还是排队调用的**规则**。这并不是说 AutoConnection 总会排队。

如果需要由工作线程的事件循环处理槽，通常把独立的 `QObject` Worker 移到工作线程，再将信号连接到 Worker 的槽。此时 AutoConnection 根据 Worker 的线程归属选择调用方式；跨线程时，排队调用会进入工作线程的事件队列。
