# 问答1：为什么不把耗时槽直接写在 `QThread` 子类中？

## 问题

为什么 `QThread` 子类中的普通槽函数可能仍在创建线程中执行？`run()` 和普通槽函数的线程行为有什么区别？如何让耗时槽在工作线程中执行？

## 回答

关键是区分 `run()` 和普通槽函数：它们虽然都写在 `QThread` 子类中，但执行位置不同。

```cpp
class MyThread : public QThread
{
    Q_OBJECT

public slots:
    void doWork();

protected:
    void run() override;
};

MyThread thread; // 在 GUI 主线程创建
thread.start();  // Qt 在新线程中调用 run()
```

- `run()` 是特殊的：调用 `start()` 后，Qt 在新线程中调用它。
- `doWork()` 是普通槽。`MyThread` 对象本身仍属于创建它的线程。如果信号通过排队连接调用 `doWork()`，它会在对象所属的线程执行；对象是在 GUI 主线程创建的，因此槽会在 GUI 主线程执行。

更精确地说，**排队槽在哪执行，取决于接收对象的线程归属**。直接连接则会在发出信号的线程里立即执行槽。因此，不能只因为槽函数写在 `QThread` 子类中，就认为它会自动运行在工作线程。

常见的 Worker-object 写法是创建一个独立的 `Worker` 对象，再调用 `worker->moveToThread(&thread)`。这样，排队给 `Worker` 的槽和事件就会由工作线程处理，而 `QThread` 管理对象仍留在创建它的线程中。

参考：[Qt 5.12 `QThread` 源码与说明](https://github.com/qt/qtbase/blob/v5.12.12/src/corelib/thread/qthread.cpp)
