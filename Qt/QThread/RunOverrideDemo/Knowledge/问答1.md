# 问答1：重写 `run()` 和在 `QThread` 子类中定义普通槽有什么区别？

## 问题

当前 `RunOverrideDemo` 中，`WorkThread` 继承 `QThread`，并把耗时任务写在 `run()` 里。为什么不能简单地给 `QThread` 子类添加一个 `doWork()` 槽，然后认为这个槽会自动在工作线程执行？

## 回答

关键是区分 **`QThread` 对象的线程归属**和**`run()` 的执行线程**。它们虽然都关联同一个 `QThread` 对象，但并不因此在同一线程执行。

```cpp
class WorkThread : public QThread
{
    Q_OBJECT

protected:
    void run() override;
};

WorkThread thread; // 在 GUI 主线程创建
thread.start();    // Qt 在新线程中调用 run()
```

- `start()` 会启动底层线程，并在新线程中调用重写的 `run()`。因此，把一次性任务写在 `run()` 里，任务代码确实会在工作线程执行。
- `QThread` 对象本身仍属于创建它的线程。本例的 `WorkThread` 由 GUI 窗口创建，所以对象归属 GUI 主线程。
- `doWork()` 如果是 `WorkThread` 的普通槽，通过排队连接调用时，会在接收对象的归属线程执行；因此它可能在 GUI 主线程执行，并不会因为槽写在 `QThread` 子类里就自动转到工作线程。

直接连接则会在发出信号的线程里立即执行槽，所以槽的执行位置还取决于连接类型和发信号的线程。若从 `run()` 中直接调用一个普通成员函数，它会在当前工作线程执行；但如果这个函数同时访问 `QThread` 对象的成员，而 GUI 主线程也访问这些成员，就需要处理好线程安全。

## `QThread` 子类的成员数据也要注意线程安全

`QThread` 子类对象的线程归属通常仍是创建它的线程。定义在这个子类中的普通槽，如果通过排队连接调用，会按接收对象的线程归属执行，因此通常仍在创建线程（例如 GUI 主线程）执行。与此不同，重写的 `run()` 会由 `start()` 在新线程中调用。

普通成员变量本身不是 `QObject`，没有独立的线程归属；它们只是 `QThread` 对象里的数据。如果 `run()` 在工作线程访问某个成员变量，而普通槽又在 GUI 主线程访问同一份数据，就会出现跨线程共享访问，需要通过互斥锁、原子变量或清晰的单线程所有权等方式保证线程安全。

当前 `RunOverrideDemo` 没有给 `WorkThread` 添加 `doWork()` 之类的普通槽：耗时循环直接写在 `run()` 中；进度通过 `progressChanged` 信号发回 GUI；取消通过 `requestInterruption()` 通知，再由 `run()` 主动检查 `isInterruptionRequested()`。

如果需要工作线程长期接收排队槽、定时器或其他事件，常见做法是创建独立的 `QObject` Worker，并用 `moveToThread(&thread)` 将它的线程归属转到工作线程。这样，排队给 Worker 的槽和事件由工作线程的事件循环处理。

参考：[Qt 5.12 `QThread` 源码与说明](https://github.com/qt/qtbase/blob/v5.12.12/src/corelib/thread/qthread.cpp)

## 追问：什么是排队连接？

### 问题

Qt 信号和槽中的“排队连接”（`Qt::QueuedConnection`）是什么意思？信号发出后，槽会在哪个线程、什么时候执行？

### 回答

排队连接表示：发出信号时，Qt 不立即执行槽，而是把这次调用及其参数放入**接收对象所属线程的事件队列**。等该线程的事件循环处理到这次调用时，才执行槽。因此，发出信号的代码可以先继续运行。

```cpp
connect(sender, &Sender::someSignal,
        receiver, &Receiver::someSlot,
        Qt::QueuedConnection);
```

可以把流程简化为：

```text
emit 信号 → 调用进入接收线程的队列 → 事件循环取出调用 → 执行槽
```

如果接收线程正执行一个长时间不返回的槽，事件循环暂时无法处理队列中的其他调用，这些调用就要等当前槽返回。排队连接也依赖接收线程的事件循环；如果该线程没有运行事件循环，排队给它的调用就无法按通常方式及时处理。

本示例中的连接是：

```cpp
connect(&workerThread, &WorkThread::progressChanged,
        progressBar, &QProgressBar::setValue);
```

`progressChanged` 从工作线程发出，而 `progressBar` 属于 GUI 主线程。默认的 `Qt::AutoConnection` 会在这种跨线程情况下选择排队调用，因此进度条更新由 GUI 主线程的事件循环处理。工作线程本身没有调用 `exec()`，也不妨碍这个进度更新，因为排队调用是发往接收者所属的 GUI 主线程。

默认的 `Qt::AutoConnection` 会根据**发出信号时所在的线程**和**接收对象的线程归属**选择连接方式：同线程时类似直接连接，跨线程时类似排队连接。

参考：[Qt：跨线程信号和槽](https://doc.qt.io/qt-6/threads-qobject.html) · [Qt：连接类型](https://doc.qt.io/qt-6/qt.html#ConnectionType-enum)
