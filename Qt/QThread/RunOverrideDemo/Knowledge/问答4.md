# 问答4：连接方式、线程归属和 `connect()` 第五个参数

## 问题

Qt 信号和槽的连接方式有哪些？接收对象的线程归属如何影响槽函数的执行线程？`connect()` 的第五个参数表示什么，尤其是 `Qt::AutoConnection` 和 `Qt::QueuedConnection` 有什么区别？

## 回答

一个常见的 `connect()` 写法是：

```cpp
connect(sender, &Sender::someSignal,
        receiver, &Receiver::someSlot,
        Qt::AutoConnection);
```

在这个成员函数指针形式的重载中，第五个参数是连接类型 `Qt::ConnectionType`。它决定信号发出后槽如何调用；省略第五个参数时，默认使用 `Qt::AutoConnection`。它不负责改变接收对象属于哪条线程。

## 接收对象的线程归属

`QObject::thread()` 表示对象的线程归属，也称线程亲和性（thread affinity）。对象通常属于创建它的线程；调用 `moveToThread()` 后可以改变归属。排队调用（queued invocation）会由接收对象所属线程的事件循环处理。

发信号的线程是**信号实际发出时正在执行代码的线程**。它不一定等同于发送者对象的线程归属。`Qt::AutoConnection` 会在信号发出时，比较当前发信号的线程与接收对象的线程归属，再决定直接调用还是排队调用（queued invocation）。

## 常见连接方式

| 连接类型 | 行为 |
| --- | --- |
| `Qt::AutoConnection` | 默认方式。发信号时，当前线程与接收对象归属线程相同则直接调用；不同则排队到接收对象线程的事件循环，产生排队调用（queued invocation）。 |
| `Qt::DirectConnection` | 信号发出时立刻调用槽，槽在发信号的线程执行。跨线程直接调用可能不安全，尤其是槽访问接收对象或 GUI 控件时。 |
| `Qt::QueuedConnection` | 显式指定排队调用：把槽调用排到接收对象所属线程的事件队列，由该线程的事件循环稍后取出并执行槽。即使发信号和接收对象在同一线程，显式指定它也会延后执行。 |
| `Qt::BlockingQueuedConnection` | 类似排队连接，但发信号的线程会等待槽执行完成。同一线程中使用会造成死锁。 |
| `Qt::UniqueConnection` | 防止建立重复连接的标记，不是新的调用时序；可与其他连接类型组合使用。 |

可以这样区分：**`Qt::AutoConnection` 是选择规则；直接调用或排队调用（queued invocation）是实际采用的方式。**`Qt::QueuedConnection` 是显式选择排队调用的连接类型。Auto 跨线程时也会产生排队效果，但连接本身仍是 `Qt::AutoConnection`。

## 结合线程归属举例

假设 `MyThread` 对象在 GUI 主线程创建，它的线程归属仍是 GUI 主线程。即使 `run()` 在新线程里调用 `exec()`，也不会改变这个归属。

```cpp
// 按钮与 MyThread 对象都属于 GUI 主线程：AutoConnection 直接调用
connect(button, &QPushButton::clicked,
        &myThread, &MyThread::doWork,
        Qt::AutoConnection);

// 假设信号在工作线程发出，而 MyThread 对象仍属于 GUI 主线程：AutoConnection 排队
connect(worker, &Worker::someSignal,
        &myThread, &MyThread::doWork,
        Qt::AutoConnection);
```

第一种情况下，槽在 GUI 主线程直接执行；第二种情况下，槽调用排队到 `MyThread` 对象所属的 GUI 主线程，而不是排到工作线程。`exec()` 启动工作线程事件循环，但不会把 `MyThread` 对象或它的普通槽自动移过去。

## 结合 `RunOverrideDemo` 看

项目中进度信号的连接省略了第五个参数：

```cpp
connect(&workerThread, &WorkThread::progressChanged,
        progressBar, &QProgressBar::setValue);
```

这等价于使用默认的 `Qt::AutoConnection`。信号从 `WorkThread::run()` 所在的工作线程发出，`progressBar` 属于 GUI 主线程，所以 Qt 选择排队调用（queued invocation）；GUI 主线程的事件循环随后更新进度条。这个过程不要求工作线程自己的事件循环运行。

## 记忆方式

- 第五个参数选连接方式，不改变对象线程归属。
- `AutoConnection` 在发信号时根据当前发信号线程和接收对象归属线程选择方式。
- `QueuedConnection` 明确表示稍后交给接收对象线程的事件循环处理。
- `QThread::exec()` 不会改变 `QThread` 对象本身的线程归属。
