# 问答3：QThread 的 `quit()` 与 `wait()`

在这个示例中，`quit()` 和 `wait()` 都和线程退出有关，但职责不同：

- `quit()`：请求工作线程的 Qt 事件循环退出。
- `wait()`：阻塞当前调用线程，直到工作线程真正结束。

## `quit()`：请求事件循环退出

任务完成或取消时，Worker 发出自己的 `finished` 信号：

```cpp
connect(worker, &Worker::finished,
        &thread, &QThread::quit);
```

`quit()` 会让 `QThread` 管理的事件循环退出。它不会强行中断此刻正在运行的函数，也不会代替 Worker 完成清理。Worker 仍需从 `doWork()` 返回，工作线程随后才能结束。

因此，这里的 `Worker::finished` 表示“任务已经完成或决定取消”；它与 `QThread::finished` 不同，后者表示工作线程本身已经结束。

## `wait()`：等待线程结束

窗口析构时会执行：

```cpp
thread.requestInterruption();
thread.quit();
thread.wait();
```

前两行通知 Worker 尽快结束，并请求线程事件循环退出。`wait()` 随后等待工作线程完成退出和收尾。这样窗口销毁时，不会留下仍在运行的 `QThread`。

`wait()` 会阻塞调用它的线程。本例只在窗口析构时调用；如果在正常的 GUI 操作过程中等待，界面会暂停响应。任务循环会检查中断请求，所以窗口关闭时 Worker 通常会在当前小步骤结束后退出；如果任务正卡在较长的不可中断操作里，`wait()` 也会等到该操作返回。

## 在本示例中的退出顺序

1. Worker 完成任务，或检查到中断请求后准备取消。
2. Worker 发出 `Worker::finished`，连接据此请求 `QThread::quit()`。
3. Worker 从 `doWork()` 返回；`quit()` 不会打断这个正在运行的函数。
4. 工作线程的事件循环退出，线程结束并发出 `QThread::finished`。
5. 如果窗口正在析构，`thread.wait()` 会等待到线程真正完成。

## 记忆方式

- `quit()`：**发出退出请求**，面向线程的事件循环。
- `wait()`：**同步等待结束**，面向调用 `wait()` 的当前线程。
