# 问答14：成员指针指向的定时器会随 Worker 一起移动吗？

## 问题十九：成员指针与 QObject 父子关系有什么区别？

当前代码在工作线程的 `initialize()` 中创建定时器：

```cpp
timer = new QTimer(this);
```

假设把创建操作移到 Worker 的构造函数中，并且不指定父对象：

```cpp
EventWorker::EventWorker(QObject *parent)
    : QObject(parent)
{
    timer = new QTimer;
}
```

Worker 仍然在 GUI 线程中创建，随后执行：

```cpp
worker->moveToThread(&workerThread);
```

`timer` 是 Worker 的成员指针，那么这个定时器会随 Worker 一起移动到工作线程吗？为什么？“指针是类的成员”和“指向的 QObject 是它的子对象”是否是一回事？

### 我的回答

我认为定时器不会随 Worker 一起移动到工作线程。

构造 Worker 时，代码在 GUI 主线程中执行，因此通过 `new QTimer` 创建的定时器也属于 GUI 线程。之后调用 `moveToThread()`，改变的是 Worker 的线程归属。

这里没有为定时器指定父对象，Worker 与定时器之间没有建立 QObject 父子关系。我认为，仅通过成员变量保存定时器的地址，不会使定时器随 Worker 一起移动。

### 反馈与解释

对创建线程和移动过程的判断正确。需要进一步明确的是：Worker 的成员是 `timer` 这个指针，指针指向的 `QTimer` 是另一个独立对象。

```cpp
timer = new QTimer;
```

这行代码在 GUI 线程执行，因此创建的定时器属于 GUI 线程。它没有父对象，`moveToThread()` 也不会遍历 Worker 的成员指针，把指向的对象一起移动。

所以，移动 Worker 后的线程归属是：

```text
Worker 对象 → 属于工作线程
QTimer 对象 → 仍属于 GUI 线程
```

如果随后在工作线程中调用 `timer->start()`，就违反了定时器必须在所属线程启动的要求。

#### 指定父对象后会怎样？

如果在 Worker 构造函数中写成：

```cpp
timer = new QTimer(this);
```

定时器就成为 Worker 的 QObject 子对象。随后移动 Worker 时，这个定时器也会一起移动，因为 Qt 会自动移动 QObject 的子对象。

两种情况可以对比为：

| 构造函数中的创建方式 | QObject 父子关系 | 移动 Worker 时定时器是否跟随 |
| --- | --- | --- |
| `new QTimer` | 没有建立 | 不会 |
| `new QTimer(this)` | 定时器是 Worker 的子对象 | 会 |

因此，判断是否随 Worker 移动，关键要看 QObject 父子关系。仅仅把对象地址保存在成员指针中，不会建立这种关系。

当前项目是在 Worker 移动后，由工作线程执行 `initialize()` 并创建定时器，因此定时器从创建时就属于工作线程。构造函数中的两种写法用于对比说明线程归属与父子关系。

参考：[Qt 官方文档：QObject 的线程归属](https://doc.qt.io/qt-6/qobject.html#thread-affinity) · [Qt 官方文档：QTimer](https://doc.qt.io/qt-6/qtimer.html)。
