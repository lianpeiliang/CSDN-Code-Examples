# 问答6：悬空指针与野指针有什么区别？

## 我的提问

前面的排队信号槽示例涉及局部变量生命周期结束后产生的悬空指针。请进一步解释悬空指针和野指针的含义、常见产生方式，以及它们与空指针的区别，并结合代码说明使用时需要注意的问题。

## 回答

这两个词都描述指针的使用问题，但关注点不同。悬空指针曾经指向有效对象，后来对象不再存在；野指针通常指未经初始化、没有确定有效指向的指针。“野指针”并非严格统一的术语，有些资料也把悬空指针归入其中。

| 类型 | 典型情况 |
| --- | --- |
| 悬空指针 | 指向的对象已经被销毁，指针还保存着原地址 |
| 野指针 | 指针未初始化，就被拿来使用 |
| 空指针 | 明确设置为 `nullptr`，表示当前没有指向对象 |

### 悬空指针

```cpp
int *p = new int(50);

delete p;  // 整数对象被销毁
           // p 成为悬空指针

// 此时不能再通过 *p 读取或写入
p = nullptr;
```

`delete p` 销毁对象、释放存储空间，不会自动把 `p` 改成 `nullptr`。通过悬空指针访问对象属于未定义行为：可能读到旧值、读到其他数据，也可能崩溃。

前面的 Qt 示例也是同一个问题：

```cpp
void EventWorker::sendValue()
{
    int value = 50;
    emit valueReady(&value);
}
```

函数返回后，局部变量 `value` 的生命周期结束。GUI 稍后收到的地址就不能再用于读取这个变量。这里没有使用 `delete`，也一样会产生悬空指针。

### 野指针

野指针的一种典型情况是局部指针未初始化：

```cpp
void example()
{
    int *p;  // 局部指针没有初始化

    // 不能通过 *p 读写
    // 也不应该读取 p 来判断它指向哪里
}
```

这里的 `p` 从一开始就没有获得确定的有效地址。声明指针时可以先初始化：

```cpp
int *p = nullptr;
```

### 空指针

`nullptr` 是明确的“没有指向对象”的状态，可以判断、赋值，但仍然不能解引用：

```cpp
if (p == nullptr) {
    // 当前没有可访问的对象
}
```

### 容易误判的地方

- 非空不代表有效。悬空指针可能仍然非空，`if (p)` 无法证明它指向的对象还活着。
- 置空只影响这一个指针。如果另一个指针也保存着同一个地址，`p = nullptr` 不会自动修改它。

在排队信号槽场景中，尤其要留意对象的生命周期：指针能被复制进事件，不代表它指向的对象能一直活到槽执行时。
