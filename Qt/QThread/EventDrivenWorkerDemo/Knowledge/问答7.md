# 问答7：moveToThread() 与 start() 分别起什么作用？

## 问题十二：仅改变线程归属，排队槽能执行吗？

假设已经执行：

```cpp
worker->moveToThread(&workerThread);
```

但没有调用：

```cpp
workerThread.start();
```

此时 GUI 发出 `startRequested` 信号，排队到 Worker 的 `startTask()` 能执行吗？`moveToThread()` 和 `start()` 分别起什么作用？

### 我的回答

`moveToThread()` 将 Worker 对象的线程归属改为目标工作线程，`start()` 则启动该线程，使其开始运行。

此时尚未调用 `start()`，工作线程还没有开始运行，因此我认为排队到 Worker 的 `startTask()` 暂时无法执行。

### 反馈与补充

判断正确，此时 `startTask()` 暂时无法执行。

更准确地说：

- `moveToThread(&workerThread)` 改变 Worker 的线程归属，让它的排队槽和事件由目标线程处理，但不会启动线程。
- `workerThread.start()` 启动底层工作线程。本例没有重写 `run()`，默认实现会启动工作线程的事件循环。

因此，没有调用 `start()` 时，工作线程的事件循环尚未运行，排队的开始请求就无法被处理。如果之后调用 `start()`，事件循环运行起来，之前排队的请求才有机会执行。

## 追问：线程尚未启动时，这次调用是否已经入队？

### 我的提问

在 Worker 已经通过 `moveToThread()` 改变线程归属，但目标线程尚未调用 `start()` 的情况下，如果 GUI 发出信号触发排队调用，目标线程的事件队列中是否已经记录了这次调用？

### 回答

会记录下来。在上述场景中，Worker 已经归属于目标线程，排队连接也已建立，因此发出信号时，Qt 会把槽调用及参数放入目标线程的事件队列；入队不要求该线程已经启动。

可以这样理解：

```text
moveToThread()：确定由哪个线程处理 Worker 的事件
        ↓
发出信号：调用已经入队，等待处理
        ↓
start()：启动线程，本例的默认 run() 开始运行事件循环
        ↓
事件循环处理之前排队的调用
```

因此，此时是“已经排队，尚未执行”。如果始终不启动线程、运行事件循环，这次调用就无法得到处理。

参考：[Qt 6.8.3 事件投递源码：QCoreApplication::postEvent()](https://github.com/qt/qtbase/blob/v6.8.3/src/corelib/kernel/qcoreapplication.cpp#L1576)。

## 问题十三：quit() 和 wait() 分别起什么作用？

窗口关闭时，示例中会执行：

```cpp
workerThread.quit();
workerThread.wait();
```

这两个函数分别起什么作用？如果只调用 `wait()`，它会主动让工作线程退出吗？

### 我的回答

`quit()` 用于请求工作线程退出事件循环。如果工作线程正在处理事件，需要先等待当前事件处理完成。

我的理解是，工作线程退出事件循环后会发出 `finished()` 信号，随后继续进行相关资源的清理。`wait()` 则让主线程等待工作线程正常、安全地退出。

只调用 `wait()` 不会主动让工作线程退出，它只会让主线程阻塞在此处，等待工作线程结束。

### 反馈与补充

整体理解正确，可以进一步明确以下细节。

`quit()` 是请求工作线程的事件循环退出，不会强行打断正在执行的槽。当前槽正常返回后，事件循环才能完成退出；这不表示必须把队列里所有事件都处理完。

`wait()` 是阻塞调用它的线程，等待目标线程结束。本例由 GUI 线程调用，所以等待的是 GUI 线程。调用顺序大致如下：

```text
GUI 线程：调用 quit() → 进入 wait() 等待 → 等待结束后继续执行
工作线程：当前槽返回 → 事件循环退出 → run() 返回 → 完成退出
```

`finished()` 发出时，事件循环已经停止，但工作线程仍可能执行最后的清理，例如线程局部变量的析构。因此，收到 `finished()` 与通过 `wait()` 确认线程结束，含义有所不同。

只调用 `wait()` 不会主动停止线程。如果工作线程没有其他退出机制，本例这个一直等待事件的工作线程就会继续运行，GUI 线程也会一直阻塞在无超时的 `wait()` 上。

参考：[Qt 官方文档：QThread::finished()](https://doc.qt.io/qt-6/qthread.html#finished)。
