# 问答16：lambda 捕获 this 能保证在 GUI 线程执行吗？

## 问题二十一：三参数 connect() 与带上下文的连接有什么区别？

原代码通过窗口的槽函数更新进度条：

```cpp
connect(worker, &EventWorker::progressChanged,
        this, &EventDrivenWorkerDemo::updateProgress);
```

假设改成下面的写法，省略作为接收上下文的 `this`，只在 lambda 中捕获它：

```cpp
connect(worker, &EventWorker::progressChanged,
        [this](int value) {
            progressBar->setValue(value);
        });
```

Worker 仍然在工作线程中发出 `progressChanged`。这个 lambda 会在哪个线程执行？捕获了窗口的 `this`，是否就能保证在 GUI 线程更新进度条？

### 补充提问：只有三个参数的 connect() 表示什么？

我还不了解这种只有三个参数的 `connect()` 写法，希望先理解它的含义，以及各个参数分别起什么作用。

### 写法与参数解释

这里的三参数形式表示：把某个对象的信号连接到一个函数或 lambda，信号发出时执行它。

```cpp
connect(发送对象, 信号, 要执行的函数);
```

代入本题的代码：

```cpp
connect(worker,                         // 第一个参数：谁发信号
        &EventWorker::progressChanged,  // 第二个参数：哪个信号
        [this](int value) {             // 第三个参数：信号触发时执行的 lambda
            progressBar->setValue(value);
        });
```

第三个参数是一个完整的 lambda，可以理解为现场定义的一个函数。其中：

- `[this]` 捕获当前窗口的指针，让函数体能够访问窗口成员。
- `(int value)` 接收信号传来的进度值。
- `{ ... }` 是信号触发时执行的代码。

捕获 `this` 只是让 lambda 能访问窗口，没有告诉 Qt 把调用安排到 GUI 线程。这种没有接收上下文的三参数连接采用直接调用，lambda 在发出信号的线程中执行。

因此，Worker 在工作线程中发出信号时，这个 lambda 就在工作线程中执行，直接更新进度条不符合 GUI 控件的线程使用要求。

#### 增加接收上下文

如果要让 GUI 线程执行，可以增加一个上下文参数：

```cpp
connect(worker, &EventWorker::progressChanged,
        this,
        [this](int value) {
            progressBar->setValue(value);
        });
```

这里两个 `this` 的作用不同：

| 位置 | 作用 |
| --- | --- |
| 作为 `connect()` 的第三个参数 | 提供 QObject 上下文；默认的 `AutoConnection` 根据它的线程归属安排调用 |
| 写在 lambda 的 `[this]` 中 | 捕获窗口指针，让函数体能够访问窗口成员 |

窗口属于 GUI 线程，因此在收到工作线程发出的信号时，后一种写法会把 lambda 排队到 GUI 线程执行。

### 我的回答

我理解，三参数形式的这条连接采用直接调用。由于信号从工作线程发出，lambda 里的 UI 更新也会在工作线程执行，因此这样写不安全。

如果增加 `this` 作为接收上下文，连接会使用默认的自动连接方式。在当前场景中，窗口属于 GUI 线程，信号从工作线程发出，所以调用会采用排队方式，能够在 GUI 线程中更新界面。

### 反馈与补充

在当前场景中，这个判断正确。

需要进一步明确的是：加入上下文后，默认连接类型仍然是 `Qt::AutoConnection`。信号发出时，Qt 比较当前发出信号的线程与上下文对象的归属线程，决定这次调用采用直接方式还是排队方式。

本例中，发出信号的是工作线程，而窗口属于 GUI 线程，因此这次调用采用排队方式，由 GUI 线程执行 lambda。

“变成排队连接”更准确的表述是：连接类型仍是 `AutoConnection`，这次跨线程调用采用排队方式。如果信号本来就在 GUI 线程中发出，同一条连接就会直接执行 lambda。

参考：[Qt 官方文档：无上下文连接采用直接调用](https://doc.qt.io/qt-6/qobject.html#QT_NO_CONTEXTLESS_CONNECT) · [Qt 官方文档：连接类型](https://doc.qt.io/qt-6/qt.html#ConnectionType-enum)。
