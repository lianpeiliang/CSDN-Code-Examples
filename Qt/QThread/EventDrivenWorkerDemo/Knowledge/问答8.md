# 问答8：线程发出 finished() 后，为什么还可能执行清理代码？

## 我的提问

问答7中提到：“`finished()` 发出时，事件循环已经停止，但工作线程仍可能执行最后的清理，例如线程局部变量的析构。”

我对这里的“最后的清理”很好奇：既然事件循环已经停止，`run()` 也已经返回，工作线程为什么还会继续执行代码？这些清理工作由谁安排？其中提到的“线程局部变量”是什么，它们为什么要在线程退出时才析构？

## 回答

我们写的 `run()` 只是工作线程执行过程中的一部分。Qt 和 C++ 运行时还会负责线程的启动与退出。因此，`run()` 返回后，线程仍可能继续执行退出处理代码。

可以用下面的概念示意理解，这不是 Qt 的实际源码：

```text
工作线程启动
        ↓
Qt 做启动准备，调用 run()
        ↓
本例的默认 run() 运行事件循环
        ↓
事件循环退出，run() 返回
        ↓
发出 QThread::finished()
        ↓
继续执行剩余的退出清理
        ↓
底层工作线程彻底结束
```

实际清理由 Qt、编译器生成的代码和系统运行时共同完成，具体过程涉及平台实现。Qt 官方明确说明，`finished()` 发出后，线程仍可能执行清理操作，包括 `thread_local` 对象的析构。

### 线程局部变量是什么？

这里的“线程局部变量”，特指用 `thread_local` 声明的变量。每个使用它的线程各自持有一份对象，这份对象在线程退出时销毁。

例如：

```cpp
struct Resource
{
    Resource()
    {
        qDebug() << "创建线程自己的资源";
    }

    ~Resource()
    {
        qDebug() << "释放线程自己的资源";
    }
};

void someFunction()
{
    thread_local Resource resource;
}
```

假设工作线程调用这个函数：

- 第一次执行到声明时，创建属于该线程的 `resource`。
- 函数返回后，这个对象继续存在。
- 同一线程再次调用函数时，继续使用原来的那份对象。
- 该线程退出时，调用这个对象的析构函数。

如果另一个线程也调用这个函数，它会有自己独立的一份 `resource`。

### 谁负责调用析构函数？

C++ 运行时会安排调用，不需要我们手动调用。可以把它理解为：初始化这类对象时，相应的析构操作会被登记下来，在线程退出阶段执行。

因此，即使 `run()` 已经返回，线程仍可能需要执行这些析构函数。析构函数也是普通代码，里面可能释放内存、关闭文件、写日志，甚至执行很久。所以，`finished()` 发出以后，退出清理仍可能持续一段时间。

### 与普通局部变量有什么区别？

“线程局部”表示每个线程独有一份，它的生命周期与函数中的普通局部变量不同：

```cpp
void example()
{
    Resource a;               // 离开当前作用域时析构
    thread_local Resource b;  // 当前线程退出时析构
}
```

`example()` 返回时，`a` 被销毁，`b` 仍然存在。线程退出时，运行时才安排销毁该线程的 `b`，这个析构操作可能发生在 `finished()` 发出之后。

当前示例没有显式声明 `thread_local` 变量。问答7使用它举例，是为了说明：事件循环停止、`run()` 返回、发出 `finished()` 和完成所有退出清理，是退出过程中的不同阶段。

本例在 GUI 线程调用 `workerThread.wait()` 来等待工作线程结束。在当前 Windows 环境中，`wait()` 成功返回时，底层线程已经完全退出，包括线程退出时的清理。

参考：[Qt 官方文档：QThread::isFinished()](https://doc.qt.io/qt-6/qthread.html#isFinished) · [Qt 官方文档：QThread::wait()](https://doc.qt.io/qt-6/qthread.html#wait)。
