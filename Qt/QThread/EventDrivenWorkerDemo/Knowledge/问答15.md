# 问答15：有父对象的 Worker 能单独移动到工作线程吗？

## 问题二十：让窗口作为 Worker 的父对象，会影响 moveToThread() 吗？

当前窗口创建 Worker 时，没有指定父对象：

```cpp
worker = new EventWorker;
worker->moveToThread(&workerThread);
```

假设为了让窗口自动管理 Worker 的生命周期，改成：

```cpp
// this 是 GUI 线程中的窗口对象
worker = new EventWorker(this);
worker->moveToThread(&workerThread);
```

这次 `moveToThread()` 能成功把 Worker 移到工作线程吗？为什么？

### 我的回答

我认为不能成功移动。

根据前面的讨论，QObject 的父对象与子对象必须属于同一个线程。现在窗口是 Worker 的父对象，而窗口属于 GUI 线程，因此 Worker 也必须属于 GUI 线程，不能单独移动到工作线程。

### 反馈与解释

这个判断正确。这次移动会失败，Worker 仍然属于 GUI 线程。

```cpp
worker = new EventWorker(this);
```

这行代码建立了 QObject 父子关系：

```text
窗口（父对象，属于 GUI 线程）
    └── Worker（子对象，也属于 GUI 线程）
```

Qt 要求父对象与子对象属于同一线程，因此有父对象的 QObject 不能通过 `moveToThread()` 单独移动到其他线程。这次调用会输出警告，Worker 的线程归属不会改变。

#### 父类与父对象有什么区别？

这里需要区分两组术语：

| 术语 | 含义 | 本例中的例子 |
| --- | --- | --- |
| 父类、子类 | C++ 的继承关系 | `EventWorker` 继承 `QObject` |
| 父对象、子对象 | 具体 QObject 实例之间的关系 | 窗口是 Worker 的父对象 |

`EventWorker` 继承 `QObject`，不会使某个具体的 QObject 实例自动成为它的父对象。本题中的父子关系，是构造时传入窗口对象，并由 Worker 的构造函数将其传给 `QObject(parent)` 建立的。

#### 与问答14的结论有什么联系？

问答14讨论的是：移动一个没有父对象的 Worker 时，它的 QObject 子对象会跟着移动。

本题讨论的是：如果 Worker 自己还有父对象，就不能单独移动。

因此，当前项目创建 Worker 时不传窗口作为父对象，使它能够移动到工作线程；随后通过以下连接安排它的销毁：

```cpp
connect(&workerThread, &QThread::finished,
        worker, &QObject::deleteLater);
```

这样既满足 Worker 的线程归属要求，也安排了线程退出时的对象清理。

参考：[Qt 官方文档：QObject 的线程归属](https://doc.qt.io/qt-6/qobject.html#thread-affinity) · [Qt 官方文档：QObject::moveToThread()](https://doc.qt.io/qt-6/qobject.html#moveToThread)。
