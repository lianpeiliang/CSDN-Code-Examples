# 问答5：排队调用中的参数何时确定？

## 问题九：局部变量修改后，排队槽收到的值会变化吗？

仍然使用 `Qt::QueuedConnection`，Worker 执行：

```cpp
int value = 50;
emit progressChanged(value);
value = 80;
```

假设 GUI 线程此时正忙，直到这三行代码执行完后，才处理这次排队调用。

`updateProgress()` 收到的参数是 `50` 还是 `80`？为什么？

### 我的回答

`updateProgress()` 收到的参数是 `50`。

Qt 会在信号发出时，将槽调用及其参数值 `50` 封装成事件，投递到 GUI 线程的事件队列中。因此，后续对局部变量 `value` 的修改不会改变此次排队调用所携带的参数。

### 反馈与补充

回答正确，收到的是 `50`。

排队调用会在信号发出时保存参数的副本。之后把局部变量 `value` 改成 `80`，不会改变事件中已经保存的 `50`。

因此，GUI 槽收到的是这次信号发出时传递的值，而不是稍后再去读取局部变量 `value` 的当前值。

## 问题十：传递指针时，会自动复制指针指向的数据吗？

如果信号传递的参数从 `int` 换成 `int*`，指向 Worker 中一个仍然有效的成员变量，排队调用复制的是指针本身，还是会把指针指向的整数也复制一份？GUI 通过这个指针读取数据，还需要考虑线程安全吗？

### 我的回答

我目前还不确定。我的初步判断是，Qt 会把指针指向的整数也复制一份，希望进一步了解实际的复制行为。

### 反馈与解释

这里复制的是指针本身，也就是地址，不会自动复制指针指向的整数。

Qt 会复制排队调用的参数，具体复制什么取决于参数类型：

| 参数类型 | 事件中保存的副本 |
| --- | --- |
| `int` | 一个整数值，例如 `50` |
| `int*` | 一个地址，仍然指向原来的整数 |

传递指针后的关系是：

```text
Worker 中的指针 ─────┐
                    ├──→ 同一个整数
排队事件中的指针副本 ─┘
```

虽然有了两份指针，但它们指向同一份数据。因此，GUI 通过指针读取时，读取的是原来的共享数据，没有得到信号发出时的整数快照。

如果工作线程修改这个整数，而 GUI 同时读取它，又没有同步保护，就可能发生数据竞争。题目中“变量仍然有效”只保证指针没有失效，并不保证跨线程访问安全。

对于示例中的进度值，直接传递 `int` 更合适：GUI 收到一个独立的数值，不需要通过指针访问 Worker 的成员变量。

参考：[Qt 官方文档：QObject::connect()](https://doc.qt.io/qt-6/qobject.html#connect)。

## 问题十一：排队传递局部变量的地址是否安全？

假设 Worker 的某个函数中写了：

```cpp
void EventWorker::sendValue()
{
    int value = 50;
    emit valueReady(&value);
}
```

信号使用排队连接，GUI 线程直到 `sendValue()` 返回后，才执行接收槽。

这时，GUI 槽还能通过收到的指针安全地读取 `50` 吗？为什么？

### 我的回答

不能安全读取。`value` 是局部变量，`sendValue()` 返回后，它的生命周期就结束了。

GUI 线程随后执行接收槽时，收到的指针已不再指向一个有效的 `value` 对象，因此不能继续通过这个指针访问原来的数据。

### 反馈与补充

判断正确。更准确地说，`value` 是局部变量，`sendValue()` 返回后，它的生命周期结束，收到的指针成为悬空指针。

指针中保存的地址可能没有变化，但该地址处已经没有这个有效的 `value` 对象，存储空间也可能被复用。GUI 再解引用这个指针，属于未定义行为；即使碰巧读到 `50`，也不能说明安全。

这里直接传递 `int` 值就能避免这个问题：排队事件保存整数副本，不依赖原局部变量继续存在。
