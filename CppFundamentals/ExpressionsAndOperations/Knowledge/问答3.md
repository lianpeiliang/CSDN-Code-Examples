# 问答3：按值传参时的对象构造

## 提问

沿用 `main.cpp` 中的 `Trace` 类，把函数参数改为按值接收。进入函数体之前，会调用移动构造函数来创建参数 `item` 吗？为什么？

```cpp
void process(Trace item) {
    std::cout << "inside process\n";
}

int main() {
    Trace first;
    process(std::move(first));
}
```

## 我的回答（书面化）

我目前还不太确定，但认为这里会调用移动构造函数来创建参数对象 `item`。

## 批注与讲解

判断正确。参数声明为 `Trace item`，表示按值接收。`item` 是一个独立的 `Trace` 对象，而不是原对象的引用，因此需要在进入函数体之前完成初始化。

调用时，`std::move(first)` 产生一个非 `const` 的右值表达式，参数初始化会选择 `Trace(Trace&&)`，从而移动构造 `item`。构造完成后，程序才进入函数体并输出 `inside process`。

这里没有先默认构造参数再移动赋值，而是直接用实参移动构造参数对象。

### 与右值引用参数的区别

下面两种参数写法用于对比，应分别考虑：

| 参数声明 | 参数的含义 | 传入 `std::move(first)` 时 |
| --- | --- | --- |
| `Trace&& item` | 绑定到已有对象的右值引用 | 只建立引用绑定，不创建新的 `Trace` |
| `Trace item` | 独立的按值参数对象 | 创建新的 `Trace` 参数对象，调用本例的移动构造函数 |

因此，同样写了 `process(std::move(first))`，参数类型不同，就可能发生不同的实际操作。`std::move` 的类型转换与按值参数的构造仍然是两个不同的步骤。

### 按值参数如何选择构造函数

对于本例的 `void process(Trace item)`，可以进一步对比：

| 实参 | 初始化参数时调用的函数 |
| --- | --- |
| `first`，非 `const` 左值 | 复制构造 `Trace(const Trace&)` |
| `std::move(first)`，非 `const` 右值 | 移动构造 `Trace(Trace&&)` |

“按值传参”意味着参数是独立对象，但不意味着初始化参数时一定执行复制，也可能执行移动。

## 追问：移动构造参数后，用参数构造局部对象时还会移动吗？

### 提问

构造参数 `item` 和函数内的 `local` 时，分别调用移动构造还是复制构造？

```cpp
void process(Trace item) {
    Trace local(item);
}

Trace first;
process(std::move(first));
```

### 我的回答（书面化）

构造参数 `item` 时调用移动构造函数，构造函数内的局部对象 `local` 时调用复制构造函数。

### 批注

两处都判断正确。每次构造都需要单独检查当时用于初始化的表达式：

| 被构造的对象 | 初始化表达式 | 本例中调用的构造函数 |
| --- | --- | --- |
| 参数 `item` | `std::move(first)`，非 `const` 右值 | 移动构造 `Trace(Trace&&)` |
| 局部对象 `local` | `item`，左值 | 复制构造 `Trace(const Trace&)` |

`item` 虽然由移动构造创建，但后续直接使用名字 `item` 时，表达式仍然是左值。一个对象之前是如何构造出来的，并不决定后来使用它时表达式的值类别。

如果希望移动构造 `local`，需要将对应语句改为 `Trace local(std::move(item));`。调用处的 `std::move(first)` 不会使函数体内对 `item` 的所有使用都自动成为移动操作。

## 追问：按值参数加上 `const` 后，两次构造有什么变化？

### 提问

给按值参数加上 `const`，并在函数体中使用 `std::move(item)`。构造 `item` 和 `local` 时，分别调用哪种构造函数？

```cpp
void process(const Trace item) {
    Trace local(std::move(item));
}

Trace first;
process(std::move(first));
```

### 我的回答（书面化）

我倾向于认为参数 `item` 会通过复制构造创建，但不太确定；我认为局部对象 `local` 会通过移动构造创建。

### 批注与讲解

这两处判断需要修正：参数 `item` 通过移动构造创建，局部对象 `local` 通过复制构造创建。

### 构造 `item`：目标为 `const`，源对象不是 `const`

调用 `process(std::move(first))` 时，用于初始化参数的是 `std::move(first)`。`first` 没有 `const` 限定，因此这个表达式可绑定到移动构造函数的 `Trace&&` 参数，选择 `Trace(Trace&&)`。

这里正在初始化的是一个新的 `const Trace` 参数对象。`const` 限制对象初始化完成后的修改，不妨碍使用移动构造函数建立它的初始状态。并不是先创建一个 `const` 对象，再对它移动赋值。

### 构造 `local`：源对象 `item` 已经是 `const`

进入函数后，`item` 是已经构造完成的 `const Trace` 对象。`std::move(item)` 保留 `const`，返回类型为 `const Trace&&`，不能绑定到移动构造函数的非 `const` 参数 `Trace&&`。

复制构造函数的 `const Trace&` 参数可以绑定到这个对象，因此初始化 `local` 时选择 `Trace(const Trace&)`。

| 被构造的对象 | 用于初始化的源表达式 | 本例中选择的构造函数 |
| --- | --- | --- |
| `const Trace item` | `std::move(first)`，源对象非 `const` | 移动构造 `Trace(Trace&&)` |
| `Trace local` | `std::move(item)`，源对象为 `const` | 复制构造 `Trace(const Trace&)` |

需要分别分析每一步中的源与目标，不能仅根据目标声明中有 `const` 就认定不能移动构造，也不能仅根据源表达式写了 `std::move` 就认定一定发生移动构造。

## 追问：改成 `const` 引用参数后，还会构造参数对象吗？

### 提问

只把参数改成 `const Trace&`，分别判断：传参时会为 `item` 构造一个新的 `Trace` 对象吗？构造 `local` 时，调用复制构造还是移动构造？

```cpp
void process(const Trace& item) {
    Trace local(std::move(item));
}

Trace first;
process(std::move(first));
```

### 我的回答（书面化）

我的分析过程是：`std::move(first)` 返回 `Trace&&`，随后被 `const Trace&` 参数接收。因此，传参时不会为 `item` 构造新的 `Trace` 对象；函数内的 `std::move(item)` 返回 `const Trace&&`，所以 `local` 通过复制构造创建。

### 批注

两项判断都正确。分析中的箭头应理解为先进行表达式转换，再将参数引用绑定到已有对象，而不是把 `Trace&&` 再强制转换成 `const Trace&`，也没有在这一步创建新的 `Trace`。

`std::move(first)` 仍然指代原来的 `first`，`const Trace& item` 可以直接绑定到它。因此，参数只建立引用关系，不调用 `Trace` 的复制构造或移动构造函数。

进入函数后，通过 `item` 访问对象时，类型带有 `const` 限定。`std::move(item)` 保留这个限定，返回 `const Trace&&`，不能匹配 `Trace(Trace&&)`，但可以绑定到复制构造函数的 `const Trace&` 参数，所以复制构造 `local`。

注意，原来的 `first` 本身仍然是非 `const` 对象。`const Trace&` 限制的是通过这个引用进行的访问，并没有把原对象本身改成 `const`。
