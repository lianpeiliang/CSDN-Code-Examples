# 问答2：具名右值引用与函数参数

## 提问：右值引用参数用于构造对象时，会发生移动吗？

沿用 `main.cpp` 中的 `Trace` 类，下面函数中的 `Trace local(item);` 会调用复制构造还是移动构造？为什么？

```cpp
void process(Trace&& item) {
    Trace local(item);
}

int main() {
    Trace first;
    process(std::move(first));
}
```

## 我的回答（书面化）

这里会调用复制构造函数。虽然 `item` 声明为 `Trace&&`，但在函数体内直接使用名字 `item` 时，这个表达式是左值。

## 批注

判断正确。需要区分参数的声明类型与使用它时表达式的值类别：参数类型为 `Trace&&`，并不意味着后续每次使用 `item` 都是在使用右值表达式。

调用 `process(std::move(first))` 时，`std::move(first)` 允许右值引用参数 `item` 绑定到原来的 `first`，这一步没有创建新的 `Trace` 对象。

进入函数后，`Trace local(item);` 使用左值表达式 `item` 初始化新对象，因此选择 `Trace(const Trace&)`，调用复制构造函数。

如果希望在函数内移动构造 `local`，应明确写成：

```cpp
void process(Trace&& item) {
    Trace local(std::move(item));
}
```

这时是 `std::move(item)` 的转换使初始化选择 `Trace(Trace&&)`。绑定右值引用与实际执行移动构造是不同的步骤。

## 追问：具名右值引用传给重载函数时，选择哪个版本？

### 提问

最后两行分别会调用哪个版本的 `check`？

```cpp
void check(const Trace&) {
    std::cout << "const Trace&\n";
}

void check(Trace&&) {
    std::cout << "Trace&&\n";
}

Trace first;
Trace&& ref = std::move(first);

check(ref);
check(std::move(ref));
```

### 我的回答（书面化）

第一行 `check(ref)` 调用 `void check(const Trace&)`，第二行 `check(std::move(ref))` 调用 `void check(Trace&&)`。

### 批注

两行都判断正确。直接使用名字 `ref` 时，表达式是左值，不能绑定到 `Trace&&` 参数，因此第一行选择 `const Trace&` 版本。

第二行的 `std::move(ref)` 是将亡值，属于右值，可以绑定到 `Trace&&`。虽然 `const Trace&` 也能绑定到这个右值，但在当前两个重载中，`Trace&&` 版本更优，因此选择该版本。

这两次调用的输出为：

```text
const Trace&
Trace&&
```

判断函数重载时，要看调用处实参表达式的值类别，不能只根据 `ref` 声明时使用了 `&&` 就认为它始终会选择右值引用版本。

## 追问：调用右值引用重载就会执行移动构造吗？

### 提问

沿用前面的 `first` 和 `ref`，执行下面这次调用时，会调用 `Trace` 的移动构造函数吗？为什么？

```cpp
check(std::move(ref));
```

对应的函数体仍然只有输出：

```cpp
void check(Trace&&) {
    std::cout << "Trace&&\n";
}
```

### 我的回答（书面化）

不会调用移动构造函数，因为这里没有创建一个用于接收原对象资源的新 `Trace` 对象。

### 批注

判断正确。这次调用中，`std::move(ref)` 提供右值表达式，使程序选择 `check(Trace&&)`。随后，右值引用参数直接绑定到原来的 `first`，不会因此构造一个新的 `Trace`。函数体也只有输出，所以整个调用没有触发移动构造。

需要区分“选择接受右值引用的函数”和“执行移动构造”：前者由重载选择和引用绑定完成，后者需要有实际构造对象的操作。

“没有新对象”可以用于判断这里没有移动构造，但不能推广为没有任何移动操作。移动赋值可以作用于已有对象。另外，本例的 `Trace` 只输出日志，并不管理资源，不能把实际转移资源看作所有移动构造函数都必须执行的动作。

## 追问：对 `const` 对象使用 `std::move`，会选择移动构造吗？

### 提问

类中仍然存在 `Trace(const Trace&)` 和 `Trace(Trace&&) noexcept`。创建 `second` 时，会调用复制构造还是移动构造？为什么？

```cpp
const Trace first;
Trace second(std::move(first));
```

### 我的回答（书面化）

我认为会调用复制构造函数。`std::move(first)` 返回 `const Trace&&`，不能匹配 `Trace&&` 参数，但可以匹配 `const Trace&` 参数。我还认为这个过程中可能会发生一次强制类型转换。

### 批注

复制构造的判断和对 `const` 的分析正确。`std::move` 保留源对象的 `const` 限定，返回类型是 `const Trace&&`，其调用表达式是一个带有 `const` 限定的将亡值。

本例移动构造函数的参数是 `Trace&&`，不能绑定到这个 `const` 对象，因为那会丢弃 `const` 限定。因此，该移动构造函数不可用。

复制构造函数的参数 `const Trace&` 可以直接绑定到这个对象。`const` 左值引用既可以绑定到合适的左值，也可以绑定到合适的右值；不需要先将右值强制转换成左值，或另外创建一个临时的 `Trace`。

关于“强制类型转换”，需要区分两个步骤：

1. `std::move(first)` 本身确实执行类似 `static_cast<const Trace&&>(first)` 的转换，但没有移除 `const`，也没有创建新的 `Trace`。
2. 随后选择复制构造函数时，`const Trace&` 直接绑定到原对象，不需要额外的显式强制类型转换。真正创建新对象的操作是调用复制构造函数来构造 `second`。

不能根据写了 `std::move` 就认定一定调用移动构造；还需要检查表达式是否带有 `const`，以及类型实际提供了哪些可用构造函数。
