# 问答1：单独调用 `std::move` 时发生了什么？

## 提问

下面第二行执行时，会调用 `Trace` 的移动构造函数吗？判断依据是什么？其中 `(void)` 表示丢弃表达式的结果。

```cpp
Trace first;
(void)std::move(first);
```

## 我的回答（书面化）

我认为不会调用移动构造函数，`first` 实际上没有被移动。但我还不清楚单独执行这条语句时，具体发生了什么。

## 批注与讲解

判断正确。这里需要分别理解类型转换、表达式结果和移动构造。

### `std::move` 进行类型转换

在这个例子中，`std::move(first)` 的作用可以理解为：

```cpp
static_cast<Trace&&>(first)
```

它产生一个仍然指代原对象 `first` 的表达式，使后续代码可以选择接受右值引用的函数，例如 `Trace` 的移动构造函数。这个转换不创建新的 `Trace` 对象，不修改 `first` 的内容，也不结束其生命周期。

这里暂时只需要记住：表达式的类型或值类别发生变化，不等于已经执行了移动构造。`Trace&&` 是右值引用类型，不是另一个 `Trace` 对象。

### `(void)` 丢弃结果

`(void)std::move(first);` 在转换后丢弃表达式结果，没有用它初始化其他对象，也没有用它给其他对象赋值。因此，这一行不会触发 `Trace` 的移动构造、移动赋值或析构日志。编译器优化后，可能不需要为这条语句生成实际的机器指令。

执行完第二行，`first` 仍然是原来的对象，继续存在。

### 使用结果构造对象时，才可能执行移动构造

对比：

```cpp
Trace third(std::move(first));
```

这里是在创建一个新的 `Trace` 对象 `third`。`std::move(first)` 提供用于初始化的表达式，`third` 的初始化则选择并调用 `Trace(Trace&&)`，因此会输出移动构造日志。

表达式求值可以触发实际操作；需要逐步判断这段表达式被如何使用，而不是仅根据是否写了 `std::move` 判断是否发生移动。

## 追问：不用 `std::move` 时，调用哪个构造函数？

### 提问

如果去掉 `std::move`，下面的代码调用复制构造还是移动构造？为什么？

```cpp
Trace third(first);
```

### 我的回答（书面化）

这里会调用复制构造函数，对应类中定义的 `Trace(const Trace&)`：

```cpp
Trace(const Trace&) {
    std::cout << "copy constructor\n";
}
```

### 批注

回答正确。这里的 `first` 是一个左值表达式，可以绑定到复制构造函数的 `const Trace&` 参数，不能直接绑定到移动构造函数的 `Trace&&` 参数，因此调用复制构造函数。

对比两种初始化方式：

| 代码 | 初始化表达式 | 本例中调用的函数 |
| --- | --- | --- |
| `Trace third(first);` | `first` 是左值 | `Trace(const Trace&)`，复制构造 |
| `Trace third(std::move(first));` | `std::move(first)` 是将亡值，属于右值 | `Trace(Trace&&)`，移动构造 |

两种写法都在创建 `third`；区别是用于初始化的表达式不同，从而选择了不同的构造函数。`std::move` 的转换影响函数选择，构造函数才执行相应的操作。

## 追问：声明右值引用时，会调用移动构造函数吗？

### 提问

第二行声明了一个右值引用变量 `ref`。它会创建新的 `Trace` 对象，并调用移动构造函数吗？

```cpp
Trace first;
Trace&& ref = std::move(first);
```

### 我的回答（书面化）

我倾向于认为不会创建新的 `Trace` 对象，也不会调用移动构造函数，但对这一判断还不太确定。

### 批注

判断正确。第二行的声明类型是 `Trace&&`，因此是在初始化一个右值引用，让它绑定到现有的 `first`，不是构造一个新的 `Trace` 对象。

`std::move(first)` 产生仍然指代 `first` 的右值表达式，`ref` 随后绑定到该对象。可以把 `ref` 理解为 `first` 的另一个名字，通过 `ref` 访问的仍是同一个对象。

对比：

| 代码 | 声明的内容 | 是否创建新的 `Trace` 对象 |
| --- | --- | --- |
| `Trace&& ref = std::move(first);` | 绑定到 `first` 的右值引用 | 否，不调用移动构造 |
| `Trace third(std::move(first));` | 独立的 `Trace` 对象 `third` | 是，调用本例的移动构造函数 |

判断时，要同时看初始化表达式和被声明变量的类型。仅仅看到 `std::move`、`&&` 或 `=`，不足以认定发生了移动构造。这里的 `=` 属于引用的初始化声明，也不是移动赋值。

## 追问：用具名右值引用初始化对象时，调用哪个构造函数？

### 提问

最后一行会调用复制构造还是移动构造？

```cpp
Trace first;
Trace&& ref = std::move(first);
Trace third(ref);
```

### 我的回答（书面化）

我认为会调用移动构造函数，对应类中定义的 `Trace(Trace&&) noexcept`：

```cpp
Trace(Trace&&) noexcept {
    std::cout << "move constructor\n";
}
```

### 批注与讲解

这里需要修正：最后一行实际调用复制构造函数 `Trace(const Trace&)`。

需要区分声明中的引用类型和使用时表达式的值类别：

- 声明 `Trace&& ref` 说明 `ref` 是右值引用，可以绑定到 `std::move(first)` 所指代的对象。
- 在后续代码中直接使用名字 `ref`，这个表达式是左值；不会因为变量声明中含有 `&&` 就自动成为右值表达式。

因此，在 `Trace third(ref);` 中，移动构造函数的 `Trace&&` 参数不能直接绑定到这个左值，而复制构造函数的 `const Trace&` 可以，所以选择复制构造。

如果希望通过 `ref` 移动构造新的对象，需要再次对使用处的表达式进行转换：

```cpp
Trace third(std::move(ref));
```

这里的 `std::move(ref)` 才是可绑定到 `Trace&&` 的右值表达式，初始化 `third` 时会调用本例的移动构造函数。`ref` 仍然引用原来的 `first`，不会因为这次类型转换而变成另一个对象。

| 表达式 | 值类别 | 在本例中用于初始化新 `Trace` 时 |
| --- | --- | --- |
| `first` | 左值 | 复制构造 |
| `std::move(first)` | 将亡值，属于右值 | 移动构造 |
| `ref` | 左值 | 复制构造 |
| `std::move(ref)` | 将亡值，属于右值 | 移动构造 |
