## 与 RAII 的联系

RAII 是 **Resource Acquisition Is Initialization（资源获取即初始化）** 的缩写。它将资源的获取与管理对象的初始化关联起来，并在管理对象的析构函数中释放资源。对于具有自动存储期的局部管理对象，离开作用域时会自动析构，因此提前 `return` 也能触发资源清理。

例如，局部的 `std::unique_ptr<Worker>` 可以管理动态创建的 `Worker`。智能指针变量本身具有自动存储期，被管理的对象具有动态存储期。智能指针析构时，会销毁它拥有的对象并释放相应的存储空间。

## 复习要点

### 区分指针变量、对象与释放责任

局部原始指针的生命周期结束，不会自动销毁它指向的动态对象。手动执行 `delete` 会销毁对象并释放对应的存储空间，但不会把指针变量自动置为 `nullptr`。

`unique_ptr` 通过析构函数负责释放它拥有的对象。对象得到释放的原因是管理对象执行了清理操作；动态对象不会仅仅因为失去了所有指向它的指针就自行销毁。

对于当前拥有对象、使用默认删除器的 `std::unique_ptr<Worker> owner`：

| 操作 | 对原对象的处理 | 操作后的 `owner` |
| --- | --- | --- |
| `owner.get()` | 返回原始指针，不释放对象，不转移所有权 | 仍拥有原对象 |
| `owner.release()` | 返回原始指针，不释放对象，调用方接手释放责任 | 为空 |
| `owner.reset()` | 销毁原对象并释放其存储空间 | 为空 |
| `owner.reset(p)` | 释放原对象，并接管可合法接管的新指针 `p` | 管理 `p`；若 `p` 为空，则为空 |

不要手动释放 `get()` 返回的指针，否则智能指针后续仍可能尝试释放同一地址，导致未定义行为。`release()` 返回的指针则需要调用方显式释放，或交给另一个资源管理对象。

### 字符串对象与内部资源是不同层面的内容

构造函数参数 `name` 与成员 `name_` 是两个不同的 `std::string` 对象。`name_(std::move(name))` 仍然需要构造成员，只是通过移动构造，在适用时接管参数已有的字符缓冲区。

较短的字符串通常直接保存在字符串对象内部，不需要单独申请堆内存，移动时仍可能复制少量字符。对于使用动态缓冲区的字符串，移动通常可以减少额外分配和字符复制，降低构造过程中的内存峰值；构造完成后长期占用的内存不一定更少。

移动后的源字符串仍然有效，但标准不保证它一定为空，不能把它与移动后保证为空的 `unique_ptr` 完全等同。

### 成员初始化与函数体内赋值是两个阶段

| 写法 | 当前字符串成员的处理过程 |
| --- | --- |
| `: name_(std::move(name))` | 直接移动构造 `name_` |
| 函数体内 `name_ = std::move(name);` | 在当前成员声明没有其他初始化方式时，先默认构造成空字符串，再移动赋值 |

进入构造函数体之前，成员初始化阶段已经完成。`const` 成员可以在构造时初始化，但不能在初始化完成后通过赋值改变内容。`std::move` 不会绕过这个限制。

### 成员声明顺序决定初始化顺序

当前讨论的普通非静态数据成员按类中的声明顺序初始化。初始化列表说明每个成员如何初始化，不能改变它们的实际初始化顺序。

例如，`label_` 的初始化需要读取 `name_`，就应先声明 `name_`，再声明 `label_`，并让初始化列表保持一致。仅把 `name_` 写在初始化列表前面，不能补救错误的成员声明顺序。

对象正常销毁时，先执行其析构函数体，再按构造顺序的逆序销毁成员。

1. 运行 `main.cpp` 前，先预测完整的输出顺序。
