# 问答2：临时对象与所有权

## 提问：匿名智能指针管理的对象什么时候析构？

如果明确创建一个匿名智能指针，A 会在输出 `After` 之前还是之后被析构？

```cpp
auto first = std::make_unique<Worker>("A");
std::unique_ptr<Worker>{std::move(first)};
std::cout << "After\n";
```

## 我的回答（书面化）

A 会在输出 `After` 之前被析构。

## 批注

判断正确。第二行明确创建了一个临时的 `std::unique_ptr<Worker>` 对象，通过移动构造接管 A 的所有权，此时 `first` 为空。

这个临时智能指针会在该完整表达式结束时，也就是第二行的分号处被析构。它的析构会销毁 A 并释放其存储空间，随后程序才执行输出 `After` 的语句。

这三行代码的输出顺序为：

```text
A constructed
A destroyed
After
```

后续 `first` 自身析构时，因为它已经为空，不会再次销毁 A。

## 追问：可以手动释放 `get()` 返回的指针吗？

### 提问

`get()` 返回原始指针，不转移所有权。执行 `delete observer` 后，再离开这个作用域，会有什么问题？

```cpp
{
    auto owner = std::make_unique<Worker>("A");
    Worker* observer = owner.get();

    delete observer;
}
```

### 我的回答（书面化）

我认为会发生二次析构，进而造成无法预期的错误。

### 批注

对重复释放风险的判断正确，但应更准确地表述为“重复释放导致未定义行为”，不能保证程序只是调用两次析构函数，也不能保证一定崩溃。

`observer` 只是临时访问对象的非拥有指针。`delete observer` 已经销毁 A 并释放对应的存储空间，却不会通知 `owner`，也不会使 `owner` 自动变空。此时两个指针保存的地址都已失效。

离开作用域时，`owner` 的析构函数仍会调用删除器，尝试再次释放该地址，产生未定义行为。

正确用法是去掉 `delete observer`，将释放责任留给 `owner`。通过 `observer` 访问对象时，还必须确保被管理对象仍然存活。

## 追问：`release()` 会销毁对象吗？

### 提问

`release()` 会返回原始指针，并使智能指针放弃所有权。执行第二行后，A 会立即析构吗？后续应该由谁负责释放它？

```cpp
auto owner = std::make_unique<Worker>("A");
Worker* raw = owner.release();
```

### 我的回答（书面化）

A 不会立即析构。后续需要通过 `raw` 释放它。

### 批注

判断正确。`release()` 不会销毁对象或释放其存储空间，只会返回原来的指针并将 `owner` 置空。此后，`owner` 析构时也不会释放 A。

“由 `raw` 负责释放”需要理解为释放责任转交给了取得该指针的调用方。`raw` 本身只是原始指针，不具备自动释放行为；需要显式执行 `delete raw`，或者将对象交给另一个合适的资源管理对象。

手动释放的写法为：

```cpp
delete raw;
raw = nullptr;
```

也可以重新交给智能指针管理：

```cpp
std::unique_ptr<Worker> newOwner(raw);
```

这两种方式是不同的后续处理选择，不能先手动释放，再用同一个地址构造智能指针。如果取得 `raw` 后既不释放也不转交管理，仍会造成内存泄漏。

## 追问：`reset` 替换对象时，构造与析构的顺序是什么？

### 提问

`reset(p)` 会释放原来管理的对象，并接管 `p`。下面这段代码的完整输出顺序是什么？注意 B 的构造和 A 的析构谁先发生。

```cpp
{
    auto owner = std::make_unique<Worker>("A");
    owner.reset(new Worker("B"));
    std::cout << "End\n";
}
```

### 我的回答（书面化）

程序先构造 A，再构造 B，随后析构 A，接着输出 `End`，最后在离开作用域时析构 B。

完整输出为：

```text
A constructed
B constructed
A destroyed
End
B destroyed
```

### 批注

顺序完全正确。调用 `reset` 之前，必须先计算实参 `new Worker("B")`，因此 B 的构造先于 A 的析构发生。

随后 `reset` 释放原来管理的 A，并使 `owner` 管理 B。程序输出 `End` 后离开作用域，`owner` 自动析构，进而销毁 B 并释放其存储空间。

## 追问：`release()` 与无参数的 `reset()` 有什么区别？

### 提问

`owner.release()` 和不带参数的 `owner.reset()` 都会让 `owner` 变为空，它们对原来管理的对象有什么不同的处理？

### 我的回答（书面化）

`release()` 会返回原始指针，并使智能指针放弃所有权；`reset(p)` 会释放原来管理的对象，并接管 `p`。因此，执行 `release()` 后，原来管理的对象仍然存在；执行 `reset` 时，原来管理的对象会被释放。

### 批注

核心区别判断正确：`release()` 放弃所有权但不释放对象，调用方需要接手后续的释放责任；`reset()` 则会释放原来管理的对象。

需要区分题目中的 `reset()` 与回答中的 `reset(p)`：无参数的 `reset()` 释放原对象后让智能指针变空；`reset(p)` 释放原对象后管理传入的 `p`，只有 `p` 为空时，智能指针才会变空。这里假设 `p` 是可合法接管的新指针，并非原来正在管理的同一个指针。

对于原本拥有对象的 `std::unique_ptr<Worker>`，这些操作的区别如下：

| 操作 | 原对象是否释放 | 操作后的智能指针 | 返回值 |
| --- | --- | --- | --- |
| `owner.get()` | 否 | 仍拥有原对象 | 原始指针，不转移所有权 |
| `owner.release()` | 否 | 为空 | 原始指针，释放责任交给调用方 |
| `owner.reset()` | 是 | 为空 | 无 |
| `owner.reset(p)` | 是 | 管理 `p` | 无 |
