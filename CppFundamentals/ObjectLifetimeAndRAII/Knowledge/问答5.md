# 问答5：成员初始化顺序与析构顺序

## 提问

沿用 `main.cpp` 中的 `Worker` 类，下面的代码在创建 `Group group;` 时，`first_` 和 `second_` 谁先构造？成员声明顺序与初始化列表顺序不同时，以哪个为准？

```cpp
class Group {
public:
    Group()
        : second_("second"), first_("first") {
    }

private:
    Worker first_;
    Worker second_;
};
```

## 我的回答（书面化）

我目前不清楚成员的构造顺序由什么决定，之前没有特别关注成员声明顺序与初始化列表顺序的关系，希望进一步了解这个规则。

## 讲解与批注

### 成员按声明顺序初始化

对于这里的普通非静态数据成员，初始化顺序由它们在类中的声明顺序决定，而不是由构造函数初始化列表的书写顺序决定。

```cpp
private:
    Worker first_;   // 先声明，先构造
    Worker second_;  // 后声明，后构造
```

因此，即使初始化列表先写了 `second_`，实际执行时仍然先使用 `"first"` 构造 `first_`，再使用 `"second"` 构造 `second_`，然后才进入 `Group` 的构造函数体。

初始化列表负责说明每个成员如何初始化，但不能改变成员的初始化顺序。

### 成员按构造顺序的逆序析构

当这个 `Group` 对象正常销毁时，先执行 `Group` 自身的析构函数体，再按逆序销毁成员：先 `second_`，后 `first_`。本例没有自定义 `Group` 析构函数，其隐式生成的析构函数体没有额外输出。

对于这段代码：

```cpp
{
    Group group;
}
```

完整输出为：

```text
first constructed
second constructed
second destroyed
first destroyed
```

### 初始化列表建议与声明顺序一致

为了让代码的书写顺序与实际执行顺序一致，建议改写为：

```cpp
class Group {
public:
    Group()
        : first_("first"), second_("second") {
    }

private:
    Worker first_;
    Worker second_;
};
```

两种写法的实际构造顺序相同，但改写后更容易阅读。若某个成员的初始化需要读取另一个成员的值，应把被依赖的成员声明在前，确保使用它时已经完成初始化。

## 追问：初始化成员时，可以使用声明在它后面的成员吗？

### 提问

下面的代码希望先保存名字，再用名字生成标签。这段初始化安全吗？`label_` 使用 `name_` 时，`name_` 已经构造完成了吗？

```cpp
class WorkerInfo {
public:
    explicit WorkerInfo(std::string name)
        : name_(std::move(name)),
          label_(name_ + "!") {
    }

private:
    std::string label_;
    std::string name_;
};
```

### 我的回答（书面化）

这段初始化不安全。由于成员声明中 `label_` 位于 `name_` 之前，`label_` 会先初始化。但它的初始化又依赖 `name_`，此时 `name_` 尚未构造完成，因此不能安全使用。

### 批注

分析正确。更准确地说，初始化 `label_` 时，`name_` 尚未开始构造。对这个尚未构造的 `std::string` 执行字符串拼接，会导致未定义行为。

即使初始化列表先写了 `name_`，也不能改变实际的成员初始化顺序。这里应调整成员声明，将被依赖的 `name_` 放在前面，并让初始化列表保持相同顺序：

```cpp
class WorkerInfo {
public:
    explicit WorkerInfo(std::string name)
        : name_(std::move(name)),
          label_(name_ + "!") {
    }

private:
    std::string name_;
    std::string label_;
};
```

修复后，先完成 `name_` 的构造，再用它初始化 `label_`，最后进入构造函数体。
